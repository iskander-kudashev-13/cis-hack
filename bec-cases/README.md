# Библиотека кейсов BEC Guard

Каждый кейс — YAML-карточка: кто атакует, какие каналы контролирует, какие события и
сигналы возникают, где должна сработать защита и что сделает Devin, если кейс пропущен.

## Структура
- `schema/signals.yaml` — словарь сигналов, веса (эвристика, не откалиброваны), пороги риска
- `schema/events.yaml` — типы событий, действия, «чистые» каналы подтверждения
- `cases/*.yaml` — 6 атак + 1 контрольный честный кейс
- `validate.py` — проверка согласованности карточек (`pip install pyyaml && python validate.py`)

## Кейсы
| id | Схема | Реальный аналог | Ловим на этапе | Действие |
|---|---|---|---|---|
| bec-01 | Взлом почты поставщика + дипфейк-звонок в банк | синтетический | payment_created | hold |
| bec-02 | Перехват переписки, «мы сменили банк» | Toyota Boshoku, ~$37M | vendor_bank_changed | hold |
| bec-03 | Поддельный счёт с похожего домена | Facebook/Google, ~$122M | email_received | block |
| bec-04 | Дипфейк-видеозвонок «CFO», серия переводов | Arup, ~$25M | payment_created | hold |
| bec-05 | Подмена зарплатных реквизитов | типовая схема IC3 | vendor_bank_changed | hold |
| bec-06 | Ночная смена реквизитов через API ERP | сценарий слайдов | vendor_bank_changed | hold |
| legit-01 | Поставщик честно сменил банк | контроль ложных срабатываний | — | allow |

## Как использовать
1. **Генератор демо** проигрывает `events` как поток событий.
2. **Тест**: детектор должен выдать `expected` по каждой карточке, а `legit-*` — не срабатывать.
3. **Цикл с Devin**: новый пропущенный кейс → новая карточка → тест падает → Devin
   выполняет `devin_task`, прогоняет все карточки, открывает PR.

Поле `visible_to` у событий показывает, кто что видит: почта поставщика, ERP покупателя,
банк, банк получателя. Колонка «видимый» в `validate.py` — риск без интеграции с почтой
поставщика и банком получателя.
