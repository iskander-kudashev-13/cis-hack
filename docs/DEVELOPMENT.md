# Scam Weather · документ по разработке

21 ноября 2026 · CIS Sprint × Devin · трек Protect the big guy

## 1. Что это за система

Scam Weather — сеть, через которую банки за секунды предупреждают друг друга о счетах мошенников (дропов). Банк жертвы подтверждает BEC-кейс и публикует сигнал о счёте получателя. Остальные банки получают сигнал заранее, хранят его у себя и при следующем переводе на этот счёт отправляют платёж на проверку. Сигнал можно отозвать.

Простое объяснение: [`scam-weather-story.html`](scam-weather-story.html). Архитектура: [`ARCHITECTURE.md`](ARCHITECTURE.md), схема по времени: [`architecture-v2.html`](architecture-v2.html).

### Три принципа

1. **Данные клиентов не покидают банк.** IBAN превращается в HMAC с ключом группы. Полезная нагрузка шифруется отдельно под каждый банк-получатель.
2. **Hub слепой и не стоит на пути платежа.** Он проверяет подпись и порядок версий, раскладывает шифротекст по ящикам и ведёт журнал с цепочкой хэшей. Проверка платежа идёт по локальному кэшу банка без сетевого запроса.
3. **Devin пишет код, а не принимает решения.** Он подключает новые банки: пишет адаптер формата, тесты и открывает PR. Решение о платеже принимает детерминированный код банка.

## 2. Компоненты в репозитории

| Компонент | Путь | Что делает |
| --- | --- | --- |
| Протокол | `server/internal/protocol` | Конверт, полезная нагрузка, подпись Ed25519, шифрование X25519 + HKDF + AES-GCM, HMAC индикатора, нормализация IBAN |
| Hub | `server/internal/hub` | `POST /v1/signals`, `POST /v1/signals/{id}/revisions`, `GET /v1/inbox`, `POST /v1/inbox/{id}/ack`, `GET /v1/members`. Проверка токена, подписи, аудитории, ревизии. Журнал с цепочкой хэшей. Пауза для демонстрации сбоя |
| Узел банка | `server/internal/node` | Публикация и отзыв, опрос ящика раз в секунду, проверка подписи, расшифровка, кэш «максимальная ревизия побеждает», срок жизни, статус канала (STALE через 10 с), локальная проверка платежа |
| Адаптеры | `server/internal/adapters` | Формат каждого банка → общая форма. Bank A (JSON кейсов), Bank B (JSON core banking). Bank C (ISO 20022 pacs.008) — задача для Devin. Conformance-тест на фикстурах |
| Стенд | `server/internal/demo` | Hub + Bank A + Bank B в одном процессе. Узлы ходят в hub по HTTP со своими токенами. API консоли `/api/*`, SSE-лента, запуск Devin |
| Точка входа | `server/cmd/scamweather` | Один бинарник: hub, узлы, API и раздача собранной консоли |
| Консоль | `web/` | Vite + React + TypeScript + Tailwind, тёмная тема в стиле tp-crm. Страницы Live demo, Signals, Hub view, Onboarding |

Структура бэкенда повторяет tp-lobby-back (`cmd/…` → `internal/…`, multi-stage Dockerfile), но на стандартном `net/http` вместо gin: меньше зависимостей, сборка за секунды. Консоль берёт токены и плотную вёрстку tp-crm, SSE-ленту по образцу `audit-stream` оттуда же.

## 3. API консоли

| Метод | Что делает |
| --- | --- |
| `GET /api/state` | Полное состояние стенда: Bank A, Bank B, hub, лента событий |
| `GET /api/events` | SSE, событие `state` при каждом изменении и раз в секунду |
| `POST /api/bank-a/publish` | Bank A публикует сигнал по трём кейсам |
| `POST /api/bank-a/retract` | Bank A отзывает сигнал (ревизия 2) |
| `POST /api/bank-b/evaluate` | `{"payment_id":"pay-match" \| "pay-control"}` → решение Bank B |
| `POST /api/hub/pause` | `{"paused":true}` — имитация сбоя hub |
| `POST /api/reset` | Сброс стенда |
| `POST /api/onboarding/devin` | Запуск сессии Devin через API, если задан `DEVIN_API_KEY`, иначе возвращает готовый промпт |

## 4. Запуск локально

```bash
cd server && go test ./...
```

```bash
cd web && npm ci && npm run build
```

```bash
cd server && go run ./cmd/scamweather
```

Консоль откроется на http://localhost:8080. Для разработки UI: `cd web && npm run dev` (прокси на :8080). Если порт занят: `PORT=8090 go run ./cmd/scamweather`.

Docker из корня репозитория:

```bash
docker build -t scam-weather . && docker run -p 8080:8080 scam-weather
```

## 5. Что проверено

`go test ./...` покрывает:
- сквозной сценарий через реальный HTTP: APPROVED → публикация → синхронизация → REVIEW_REQUIRED, контрольный платёж APPROVED, отзыв → APPROVED, сброс;
- hub не хранит индикатор в открытом виде, журнал проходит проверку цепочки;
- подделанная подпись и публикация от имени чужого банка отклоняются;
- при паузе hub синхронизация падает, но проверка платежа работает по кэшу;
- порядок ревизий: дубликат и поздний v1 после отзыва не применяются, истёкший сигнал не применяется;
- conformance адаптеров на фикстурах, Bank C пропускается до появления адаптера.

Ручной прогон сервера: ACK от Bank B приходит примерно за 0,4 с при опросе раз в секунду.

## 6. Как подключить Devin

### Что нужно сделать один раз

1. Войти в Devin (app.devin.ai) аккаунтом команды хакатона.
2. В Settings → Integrations подключить GitHub и дать доступ к репозиторию `iskander-kudashev-13/cis-hack`. Без этого Devin не сможет склонировать приватный репозиторий и открыть PR.
3. Для запуска из консоли: в Settings → API Keys создать ключ и передать его серверу через переменную окружения `DEVIN_API_KEY`. Ключ не коммитить.

### Задача для демо: подключить Bank C

Готовый промпт лежит в `server/internal/demo/demo.go` (`DevinPrompt`) и показывается на странице Onboarding. Коротко: в ветке `devin/bank-c-adapter` написать `adapters/bankc.go` для ISO 20022 pacs.008, зарегистрировать его, добавить тесты, прогнать `go test ./...` (TestConformance/bank-c должен стать PASS вместо SKIP) и открыть черновой PR.

Два способа запуска:
- **Вручную.** Нажать «Start Devin session» на странице Onboarding без ключа, скопировать промпт и вставить в новую сессию Devin.
- **Через API.** Запустить сервер с `DEVIN_API_KEY`. Кнопка создаёт сессию через `POST https://api.devin.ai/v1/sessions` и показывает ссылку на неё.

Сессия идёт минуты, поэтому запускаем её в начале демо или заранее и на сцене показываем PR, diff и зелёный тест.

### Как это выглядит в продукте

Банк выпускает новую версию своей схемы → Scam Weather запускает сессию Devin через API → Devin обновляет адаптер и тесты → черновой PR с результатами conformance → инженер банка проверяет и мержит.

## 7. Деплой и демо

### Что нужно для деплоя

Один контейнер на любом хостинге с Docker. На машине установлен Railway CLI, это самый короткий путь:

1. `railway login` (вход делает человек в браузере).
2. Из корня репозитория: `railway init`, затем `railway up`. Railway соберёт `Dockerfile`.
3. В переменных сервиса задать `PORT=8080`, при необходимости `DEVIN_API_KEY`.
4. `railway domain` выдаст публичный URL. Проверить `GET /healthz` и консоль.

Запасные варианты: Fly.io или VPS с `docker run`, как в tp-lobby-back. Vercel не подходит для Go-сервера с SSE и фоновым опросом.

Ограничение демо: состояние в памяти, один экземпляр. Масштабировать нельзя, рестарт сбрасывает стенд. Для показа это нормально.
