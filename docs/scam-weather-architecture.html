CIS Sprint × Devin · трек «Protect the big guy» · черновик v0.2

Банки делятся сигналами о мошенничестве. Оркестратор ничего не видит и ничего не может подделать.

Сеть, в которой банк жертвы BEC за секунды предупреждает банк получателя, пока деньги ещё на счёте дропа. Сырые данные не покидают банки, а каждый новый банк подключает Devin.

Принцип 1Чувствительное — только внутри банка: хэш, подпись, шифрование делает узел банка
Принцип 2Оркестратор пересылает шифротекст и не может прочитать или изменить сигнал
Принцип 3Devin пишет код решений заранее. В момент платежа решает детерминированный код банка
Схема

У каждого банка свой узел, оркестратор только пересылает

Банки сами подключаются наружу по mTLS, входящие порты не нужны. Пунктир вокруг узла — контур банка.

Минимизация данных

Что выходит из банка, а что никогда

уходит, зашифровано
  • HMAC(ключ группы, IBAN) — хэш счёта
  • тип сигнала: bec_beneficiary, suspected_mule
  • уровень доказанности и код причины
  • диапазон суммы, например «100–500 тыс.»
  • срок годности и версия
не уходит никогда
  • IBAN, имена, ИНН, данные KYC
  • балансы, выписки, история операций
  • точные суммы
  • свободный текст и вложения

Схема проверяется на узле отправителя до шифрования: поле, которого нет в схеме, узел не отправит. После шифрования оркестратор содержимое проверить не может, поэтому проверка обязана быть на узлах.

Один сигнал глазами двух сторон

Что видит оркестратор и что видит банк B

// хранится в базе оркестратора
{
  "envelope": {
    "signal_id": "sig_0192",
    "revision": 1,
    "issuer": "bank-a",
    "audience": "group-uae-bec",
    "kind": "bec_beneficiary",
    "expires_at": "2026-11-22T08:00Z",
    "prev_hash": "9f3c…e1"
  },
  "payload": "eyJhbGciOiJFQ0RILUVTIiwi…"  // JWE для B и C
  "signature": "ed25519:4b1a…c7"  // ключ банка A
}

Ни IBAN, ни хэша счёта, ни суммы. Изменить конверт нельзя: подпись перестанет сходиться.

// подпись банка A проверена, payload расшифрован ключом банка B
{
  "indicator": { "type": "account_hmac", "value": "hmac:7d2e…a0" },
  "evidence_level": "issuer_analyst_verified",
  "reason_code": "confirmed_bec_case",
  "amount_band": "100k-500k",
  "first_seen": "2026-11-21T07:52Z"
}
// локально: hmac совпал со счётом клиента банка B
→ policy: account_role = own_customer → freeze_outgoing, open_case

Банк B сопоставляет хэш со своими счетами, не узнавая IBAN из сигнала. Решение принимает его собственная политика.

Маппер

Как событие сети превращается в решение банка

Маппер — это три слоя внутри узла банка. Тот же путь работает в обратную сторону: подтверждённый внутренний кейс превращается в событие для сети.

1

Адаптер формата

Общая схема ↔ формат банка: JSON, ISO 20022 pacs.008, CSV. Нормализация IBAN — если банки нормализуют по-разному, хэши не совпадут.

генерирует Devin
2

Политика банка

Тип сигнала × уровень доказанности × роль счёта → действие. Декларативный файл, которым владеет антифрод банка.

черновик предлагает Devin, утверждает Fraud Risk банка
3

Интеграция

Запись в движок правил, Kafka или систему кейсов банка.

генерирует Devin 
# policy.yaml банка B — владелец Fraud Risk, Devin только предлагает изменения
on_signal: bec_beneficiary
rules:
  - when: { account_role: own_customer, evidence: issuer_analyst_verified }
    action: freeze_outgoing     # счёт нашего клиента похож на дропа
    open_case: true
    max_duration_h: 24
  - when: { account_role: payee_of_own_customer }
    action: review              # наш клиент собирается платить на этот счёт
  - when: { evidence: suspected }
    action: score_plus_30       # слабый сигнал только повышает риск
default: no_effect
expired_or_retracted: no_effect
Роль Devin

Devin пишет код решений, но сам решения не принимает

design-time Devin

Генерирует адаптеры, интеграцию, черновик политики и тесты. Открывает PR, инженер банка одобряет. Работает минуты, и это нормально.

run-time код банка

В момент платежа работает детерминированный код узла: миллисекунды, проверяемо, без внешнего агента в контуре банка.

Главный барьер таких сетей — интеграция каждого банка. Devin превращает подключение банка из проекта на месяцы в PR, который проходит общий набор проверок.

Что собираем и как показываем

Состав

  • 3 симулятора банков с разными форматами: A — JSON, B — свой JSON, C — ISO 20022 XML
  • SDK узла на TypeScript: подпись, шифрование, HMAC, проверка схемы, ACK
  • Оркестратор: пересылка шифротекста, реестр, журнал. SQLite
  • Задача Devin: подключить новый банк по примерам и проверкам на соответствие

Что останется на пилот

  • PSI вместо HMAC
  • Прямой обмен банк–банк, если потребуется
  • HSM, CA консорциума, режим «только наблюдать»
  • Юридическое согласование обмена (ОАЭ, ст. 147 и 149)
